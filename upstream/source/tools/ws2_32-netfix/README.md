# ws2_32 network fix (FH5 online on macOS Wine)

A small `ws2_32.dll` wrapper that makes Forza Horizon 5 go online (Horizon Life, Horizon Open) under the Highball
CrossOver 26.3 r28 runner on macOS.

## The finding

FH5 opens its Xbox Live UDP socket as a dual-stack IPv6 socket on port 3074:

1. `socket(AF_INET6, SOCK_DGRAM)`, `setsockopt(IPV6_V6ONLY = 0)`, `SO_REUSEADDR`, `bind([::]:3074)`
2. `WSAIoctl(SIO_UDP_CONNRESET)`: Wine stubs it, returns OK
3. `WSAIoctl(SIO_UDP_NETRESET)`: Wine does not support it, fails with `WSAEOPNOTSUPP` (10045)
4. `setsockopt(IPPROTO_IP, IP_TTL, 255)`: on macOS Wine fails with `WSAEINVAL` (10022), because macOS refuses
   IPv4 options on an IPv6 socket

When step 3 or 4 fails the game closes the socket, retries on another port and finally stays in offline mode
("This feature is not available during offline play"), even though Xbox sign-in, PlayFab and the Forza services
all work. Ruled out: the Xbox account, the network, ncrypt and the IPv6 route table.

## The fix

`ws2_32.dll` here exports every function of the original (same names and ordinals) and forwards them to the
original Wine `ws2_32` renamed to `ws2_o.dll`. It changes two things:

- `WSAIoctl(SIO_UDP_NETRESET)` is reported as success.
- When an `IPPROTO_IP` `setsockopt` fails with `WSAEINVAL` or `WSAENOPROTOOPT`, the IPv6 equivalent is applied
  instead and success is reported: `IP_TTL` -> `IPV6_UNICAST_HOPS`, `IP_MULTICAST_TTL` -> `IPV6_MULTICAST_HOPS`,
  `IP_MULTICAST_LOOP` -> `IPV6_MULTICAST_LOOP`, `IP_TOS` -> `IPV6_TCLASS`.

Verified on the tested setup (see the main README): Horizon Life online, and a Horizon Open race with 8 real players.

## Environment variables

Set with the `NOTPROTON_ENV_` prefix in the Steam launch options, like the other variables.

| Variable | Effect |
|---|---|
| `HB_NETFIX=0` | Turn the fixes off (pure pass-through) |
| `HB_NETLOG=1` | Write a UDP activity log to `Z:\tmp\hb-net.log` (`/tmp/hb-net.log` on the Mac) |

## Files

- `src/ws2fix.c`, `src/hblog.h`: the wrapper (freestanding, kernel32 only, no CRT)
- `ws2_32.def`: export list, generated by `gen_def.py` from the runner's `ws2_32.dll`. **It must match the
  exports of the runner's `ws2_32.dll`.** It was generated from the Highball CrossOver 26.3 r28 runner. For another
  runner regenerate it:
  `WRAP=socket,WSASocketW,WSASocketA,bind,connect,WSAConnect,sendto,WSASendTo,recvfrom,WSARecvFrom,WSAIoctl,setsockopt,getsockname,closesocket python3 gen_def.py <runner ws2_32.dll> ws2_o > ws2_32.def`
  (run Python in a container if you do not want it on the host)
- `build.sh`: builds `build/ws2_32.dll` in Docker (`mstorsjo/llvm-mingw`), nothing is installed on the host
- Prebuilt: `../../bin/ws2_32.dll` (SHA-256 in `../../bin/ws2_32.dll.sha256`). A rebuild with `build.sh` is
  byte-identical except for two 2-byte PE timestamp fields (file header and debug directory), so its hash
  differs (`55538ee2...` vs the prebuilt `9f3f8088...`).

`ws2_o.dll` is not included: you make it from your own runner's `ws2_32.dll`.

## Install

Follow "Step 8b" in the main README (Option B). In short: `ws2_o.dll` (a copy of the runner's `ws2_32.dll` with
its internal export name changed by `tools/pe_tools.py rename-export`) goes into the runner's
`lib/wine/x86_64-windows/` and the prefix's `system32`, `ws2_o.so` links to `ws2_32.so`, this wrapper replaces
the prefix's `system32/ws2_32.dll`, and the gamefix becomes `DLLOVERRIDES=d3d12=n;ws2_32=n,b`.

## Verify

In the game the Online tab shows Friends/Players and Horizon Open matchmakes. With `HB_NETLOG=1`, `/tmp/hb-net.log`
contains a line like `setsockopt ... level=0 opt=4 ... (wrapper forced success)`.

## Undo

Restore the backed-up `system32/ws2_32.dll`, set the gamefix back to `DLLOVERRIDES=d3d12=n`, and delete the two
`ws2_o.dll` copies and the `ws2_o.so` link. Or just set `HB_NETFIX=0`.
